# Preserved Text Specialist Boundaries

Use this reference when deciding whether a non-OZM text-related skill should be absorbed, preserved, or cleaned from OZM normal routing.

## Cleanup Rule

Do not delete an active specialist merely because OZM absorbed its governance overlap. Clean only normal-path OZM references that make the specialist look mandatory for ordinary OZM text drafting. Preserve specialists when they own domain judgment that OZM should not copy wholesale.

## Absorbed Into OZM Defaults

These mechanisms are now OZM defaults for governed text:

- `document-review`: finding validation, confidence gate, dedupe, contradiction preservation, and auto-vs-present distinction.
- `coherence-reviewer`: contradiction, terminology drift, structural ambiguity, and broken internal-reference checks.
- `feasibility-reviewer`: reality grounding and happy/nil/empty/error shadow-path checks.
- `spec-flow-analyzer`: user-flow completeness and edge-case question formulation.
- `adversarial-document-reviewer`: premise challenge, assumption surfacing, falsification, reversal-cost, and alternative-blindness pressure.
- `advanced-evaluation`: rubric, bias-control, confidence, and evaluator-process awareness.
- `product-lens-reviewer`: product-context classification, premise challenge, second-order consequence analysis, goal-requirement alignment, prioritization coherence, and opportunity-cost checks.
- `design-lens-reviewer`: information architecture, interaction states, user-flow completeness, responsive/accessibility readiness, unresolved design-decision checks, and AI-slop risk.
- `security-lens-reviewer`: attack-surface inventory, auth/authz gaps, data exposure, third-party trust boundaries, secrets posture, and plan-level threat-model prompts.
- `spec-flow-analyzer`: codebase-grounded flow mapping, entry/decision/terminal states, unhappy paths, permission boundaries, integration seams, and specific question/default-assumption output.
- `ankane-readme-writer`: README artifact structure, concise imperative prose, Ruby gem section order, single-purpose examples, compact options tables, placeholder hygiene, and HTML-comment cleanup. Its 15-word rule is retained only as an explicit style preset, not an OZM evidence or acceptance gate.

## Preserved Specialists

- `every-style-editor`: owns brand/style-guide line editing; OZM only consumes its findings as style verdicts.
- `changelog`, `onboarding`: own artifact-specific format and voice; OZM governs authority, evidence, and closeout when the artifact is OZM-governed.
- `ozm-repo-instruction-surface-management`: owns `AGENTS.md`/`CLAUDE.md` governance after OZM freezes authority, truth class, and claim ceiling.
- `best-practices-researcher` and `learnings-researcher` are archived donor history for OZM-governed work. Use `ozm-requirement-load`, `ozm-reference-method-grounding`, and `ozm-record-surface-management` for source research, prior-learning retrieval, adoption posture, and evidence promotion.

The absorbed text-review donor ids above may be restored only for an explicitly non-OZM standalone workflow. For OZM-governed text, route through `ozm-document-drafting` and represent each former persona as a logical review dimension in the Draft Issue Registry.

## Conflict Stops

- If a preserved specialist says PASS but the draft lacks claim/evidence rows, issue closure, or authority classification, keep the ceiling below `accepted_text`.
- If a specialist wants to rewrite controller-truth Plan/Goal text, require OZM owner reread and explicit controller-update authorization first.
- If a specialist assumes parallel subagents, model switching, or native task agents unavailable in the current runtime, degrade to single-thread logical roles and record the lowered proof class.
- If a specialist requires full-document loading but the project has historical packet noise, load only the active window plus cited sections unless the OZM owner authorizes bulk read.
