## 0. Pre-Start Method

Template A is a pre-start method, not a thin project outline. Run it before implementation when the final goal depends on long-running agentic coding threads, multiple contributors, external models, UI reference generation, MCP surfaces, or provider automation.

Required sequence:

| Step | Output | Failure If Missing |
| --- | --- | --- |
| `PS-00` role and claim lock | current role, claim ceiling, non-claims | later docs overclaim source/runtime maturity |
| `PS-01` objective frame | final objective, primary user, non-goals | packets optimize for local MVP slices instead of the final system |
| `PS-02` authority surfaces | repo instructions, TruthDocs index, manifests, queue | future agents cannot find the truth route |
| `PS-03` research and reference record | official/current references, reference-repo source notes, adopt/adapt/reject table | plans inherit unverified blog/UI-image assumptions |
| `PS-04` technology stack contract | exact runtime/package boundaries and rejected alternatives | later threads add dependencies opportunistically |
| `PS-05` UX interaction contract | surface inventory, layer model, coordinate basis, visible-copy rules when UI/UX is in scope | UI becomes generic or image-only instead of task-valid, or a workbench template is wrongly applied without owner adoption |
| `PS-06` provider/deep-research contract | fake-first sequence, switch defaults, live prerequisites | unadmitted provider automation sneaks into core behavior |
| `PS-07` script, smoke/probe, and proof matrix | scripts, owners, inputs, outputs, failure classes, tests, placement class | implementation cannot be verified incrementally or disposable probes pollute source |
| `PS-08` packet ladder | ordered packets, write sets, forbidden surfaces, closeout claim | future coding threads start too broad |
| `PS-09` task/goal loop | one task file per goal, blocking review gate, report-only write path | future threads run from summary docs, self-close, or mutate controller truth |
| `PS-10` final coverage audit | final acceptance rows mapped to task/goal owners | broad final claims skip unowned acceptance rows |
| `PS-11` standing autonomy contract | activation, carrier posture, one-packet evaluator, hard stops | full authorization becomes background execution or gate bypass |
| `PS-12` Goal/runtime reentry gate | post-compaction hydration receipt, current queue, current packet, claim ceiling, next authorized action | native Goal continuation bypasses OZM child hydration and owner reread |
| `PS-13` agentic loop output discipline | routine progress output contract: execution action, result, current state summary of no more than five lines | active loops drown in repeated plans or process narration |
| `PS-14` closeout receipt | files changed, residual gaps, next admissible packet | context restarts lose the project state |

Document strength rule:

- Do not replace thick documents with summaries.
- Do not shrink existing planning content during route repair.
- Split and index large content instead of stuffing the whole corpus into prompt context.
- Every new owner document must say who reads it, when it is stale, and which route index points to it.
- Every unresolved decision must be recorded as an open item with owner, decision gate, and blocking effect.

## 1. Objective And Claim Ceiling

Start every project pack with:

| Field | Template |
| --- | --- |
| Final objective | `<one durable sentence>` |
| Current phase | `pre_start_planning` |
| Current claim ceiling | `truthdocs_planning_only` |
| Non-goals | no runtime claim, no provider claim, no UI proof, no release claim |
| First implementation gate | one bounded packet after OZM requirement load and dispatch freeze |
| Proof rule | source + tests + receipts are required before any runtime maturity claim |

Required non-claim wording:

```text
These planning documents do not prove the runtime exists. They do not prove MCP servers, provider adapters, database storage, IDE UI, external-agent dispatch, or release behavior. Future implementation claims require source, executable tests, receipts, and accepted evidence.
```

## 2. Required Control Surfaces

Create or adapt this startup document set:

| Surface | Purpose |
| --- | --- |
| `AGENTS.md` | repo entrypoint, OZM anchor, code-health, environment, Git gates |
| `TruthDocs/README.md` | default reload order and document map |
| `TruthDocs/current-state.md` | compact current state, claim ceiling, active window, next packet |
| `file-state-manifest.md` | active files, planned roots, controller-truth boundaries |
| `artifact-placement-manifest.md` | allowed artifact roots and authority classes |
| `TruthDocs/planning-context-route-index.json` | machine route for context-efficient reads |
| `TruthDocs/*context-routing-index.md` | human route rationale |
| `TruthDocs/implementation-queue.json` | current packet, stale rules, write-set boundaries |
| `TruthDocs/MainTaskLoop/README.md` | task-loop index and selection rule |
| `TruthDocs/MainTaskLoop/MTL-*.md` | one text-driven task file per implementation loop |
| `TruthDocs/MainGoalLoop/README.md` | goal-loop index and 1:1 mapping invariant |
| `TruthDocs/MainGoalLoop/REVIEW-GATE-STANDARD.md` | blocking goal review standard |
| `TruthDocs/MainGoalLoop/GL-*.md` | same-number goal file for each task |
| `TruthDocs/Tasks-Reports/README.md` | only admitted TruthDocs write path for ordinary development reports |
| `TruthDocs/*content-gap-register.md` | known planning gaps and closure records |
| `TruthDocs/*sources-reference-adoption.md` | external/local references with adopt/adapt/reject posture |
| `TruthDocs/*final-acceptance-matrix.md` | acceptance levels, proof classes, go/no-go floor |
| `TruthDocs/*final-development-coverage-audit.md` | acceptance-row-to-task/goal mapping and child-packet split rules |
| `TruthDocs/*audit-feasibility-correctness-declaration.md` | bounded serious-audit declaration and non-claims |
| `TruthDocs/*standing-autonomy-goal-runtime-contract.md` | current-thread run-until-done authorization and no-background-carrier boundary |

Repository `AGENTS.md` must include a compact Goal Runtime Reentry Gate. Generic continuous-progress wording such as “持续推进”, “自动推进”, “直至完成”, `continue until done`, or standing autonomy activates the OZM agentic coding loop / standing-autonomy contract as current-thread text control, not `create_goal` or native Codex Goal. Native Goal mode applies only when the user explicitly asks for native Codex Goal, `/GOAL`, or `create_goal`, or when an active Goal already exists and must be treated as a carrier. After context compaction, resume, long wait, handoff, replay, replacement, role switch, or explicit native Goal continuation, future threads must reopen `ozone-manager`, current-phase OZM child skills, mandatory companions, repo instructions, and active owner truth surfaces before tool calls or file mutation. The receipt must name `goal_carrier`, `hydration_epoch`, `loaded_child_skills`, `mandatory_companions`, `current_queue_revision`, `current_packet`, `claim_ceiling`, and `next_authorized_action`.

Repository `AGENTS.md` must also include an Agentic Coding Loop Output Discipline. During an active agentic coding loop, standing-autonomy run, explicit native Goal continuation, or file-driven implementation loop, routine progress messages should not explain the process or repeat the plan. They should output only execution action, result, and a current state summary no longer than five lines. This rule does not suppress OZM stop notices, user-facing blockers, final closeout, requested plans, requested audits, or error reports.

Required freshness rule:

- A new owner doc makes README, route index, current-state, queue, and manifests stale until updated.
- A new task, goal, acceptance row, runtime carrier, or standing-authorization rule makes the loop indexes, coverage audit, current-state, queue, and route indexes stale until synchronized.

## 3. Technology Stack Contract

Use this stack as Template A for local-first governed MCP/agent IDE projects.

| Layer | Standard Template A | Required Boundary |
| --- | --- | --- |
| Desktop shell | Tauri | renderer has no direct filesystem, secrets, PostgreSQL, provider SDK, or acceptance authority |
| Frontend | React + TypeScript + Vite + pnpm + ESLint | UI calls typed command bridge only |
| Styling | CSS modules/custom properties, token registry | no generic dashboard kit by default |
| UI primitives | Radix primitives when admitted | accessibility still requires local labels, focus, tests |
| Icons | `lucide-react` when admitted | icon-first controls; avoid text pills where icons are expected |
| Backend | Rust | governance, records, policy, provider routing, storage, bridge logic |
| Database | PostgreSQL | durable storage only after carrier admission |
| SQL | SQLx | `.sqlx/` metadata only after storage and carrier packet |
| MCP | Rust SDK first if parity passes; TypeScript sidecar only by controller delta | no silent TypeScript backend replacement |
| Docs/help app | Astro optional | docs surface only; not runtime truth |
| WASM | pure compute only | no secrets, files, providers, SQL, acceptance decisions |
| Browser proof | Playwright | screenshot proof is supporting evidence only |
| Desktop proof | Tauri WebDriver where supported | platform-scoped; no unsupported OS claim |
| Provider route | fake provider first, live provider later | secret refs, cost/rate, retention, failure policy required |
| Deep research | fake deep research first; official API after admission; manual report import only | no unadmitted live automation |

Configuration artifact floor:

| Artifact | Standard |
| --- | --- |
| root package manager | `pnpm-workspace.yaml` only after frontend package is admitted |
| frontend package | `apps/ide/package.json`, `tsconfig*.json`, `vite.config.ts`, `eslint.config.*` |
| desktop shell | `apps/ide/src-tauri/` only in the Tauri admission packet |
| Rust workspace | root `Cargo.toml` plus crate-level `Cargo.toml` files, introduced by packet |
| database | migrations and `.sqlx/` only after PostgreSQL carrier proof |
| contracts | shared Rust contracts first; generated TS contracts only through an explicit bridge step |
| Astro | `apps/operator-docs/` only if operator docs/help are in scope |
| WASM | separate package/crate with pure inputs/outputs and no authority over records |
| MCP | host/server crate or sidecar package recorded with SDK parity decision |
| scripts | stable thin wrappers over typed APIs; no hidden business logic; ad hoc smoke/probe/inspector/harness scripts default to scratch/Temp |

Rejected by default:

- Electron, browser-only, VS Code extension, or webview alternative without controller delta.
- Renderer-local truth.
- Provider calls before fake-provider fixtures.
- PostgreSQL, SQLx, Tauri, MCP, provider, Astro, or WASM dependencies in the first contracts scaffold unless the packet admits them.

## 4. Source Layout Template

Plan source ownership before writing files.

```text
crates/
  contracts/
  core/
  security/
  providers/
  provider-fake/
  storage/
  mcp-host/
  mcp-*/
  ide-bridge/
  verification/
  ops/
packages/
  contracts/
  test-helpers/
apps/
  ide/
    src/
    src-tauri/
  operator-docs/
fixtures/
  records/
scripts/
  <thin wrappers only>
docs/
  operator/
  design-assets/
.merce/
  <runtime records only after runtime admission>
```

Boundary rules:

- `contracts` owns DTOs/enums/schema types.
- `core` owns packet, claim ceiling, role validation, closeout.
- `security` owns path, trust, redaction, permission policy.
- `providers` owns provider registry/router interfaces, not acceptance.
- `provider-fake` is deterministic and must not import live provider SDKs.
- `storage` owns PostgreSQL repositories and migrations.
- `ide-bridge` owns Tauri command DTOs and allowlist.
- `apps/ide` renderer owns UI only.
- `scripts` are stable wrappers over typed APIs, not business-logic dumps.
- Ad hoc smoke/probe/inspector/harness scripts live under the project scratch/Temp root unless a controller packet explicitly promotes them as stable `source_wrapper` records with typed-API boundaries, output contracts, negative cases, and non-claims.

## 5. Environment Dependency Route

Before local tools, runtimes, services, model caches, Docker/WSL helpers, or local provider endpoints are used:

1. Read the project environment README.
2. Read the environment manifest.
3. Load the environment session entrypoint.
4. Invoke registered environment tools when possible.
5. Do not promote scattered local paths into default behavior unless recorded in the manifest.

Template fields:

| Field | Required |
| --- | --- |
| `environment_root` | canonical local root |
| `manifest_path` | machine-readable manifest |
| `session_entrypoint` | shell script to load paths/env |
| `tool_invoker` | wrapper script for registered services |
| `archive_root` | reusable docs/scripts only |
| `excluded_large_roots` | model caches, venvs, node_modules, logs, secrets |

## 6. UI/UX Reference Gate

Use UI/UX Template A details only when the project has admitted UI/UX, Image-2, UIREF, component atlas, browser proof, visual parity, or user-facing frontend work. If UI/UX is absent or deferred, record `ux_scope=not_applicable_or_deferred` and do not force workbench surfaces into the project. If another UI model is selected, record adopt/adapt/reject posture and route later visual work to the OZM UX owner.

Load `template-a-ui-ux-reference.md` for:

- UX interaction standard and work-loop analysis;
- visible-copy and user-state rules;
- Image-2, UIREF, component atlas, and visual-reference adoption rules.

## 7. Provider And Deep Research Automation

Provider sequence:

1. profile schema;
2. fake provider;
3. budget/rate gate;
4. local provider if any;
5. live prerequisite admission;
6. live smoke with operator authorization;
7. external-agent lane integration.

Deep research route:

| Route | Status |
| --- | --- |
| fake deep research provider | required first |
| official API deep research provider | allowed after provider admission |
| manual external research report import | allowed candidate-only |
| unadmitted external-provider automation | rejected |

Automation switches must default off. Hard-disabled switches:

```json
{
  "unadmitted_live_automation_enabled": false,
  "auto_evidence_promotion_enabled": false
}
```

Allowed low-manual-cost helpers:

- generate research pack;
- copy-ready prompt;
- local mock page automation;
- watched import folder;
- pasted/file report parser;
- citation and claim validator;
- official API smoke after admission.

## 8. Implementation Packet Ladder

Template packet ladder:

| Packet | Goal | Must Not Include |
| --- | --- | --- |
| `IPK-001` | workspace scaffold and contracts shell | UI, DB migrations, MCP servers, providers |
| `IPK-002` | record fixtures | live providers, product UI |
| `IPK-003` | validator CLI/API | broad shell tools |
| `IPK-004` | fixture inventory gate | acceptance claims |
| `IPK-005` | core governance runtime slice | UI/DB/provider shortcuts |
| `SPK-*` | storage/PostgreSQL admission | before carrier proof |
| `MCP-*` | MCP host/server route | before SDK/runtime decision |
| `UIK-*` | IDE token/shell/copy/a11y/browser proof | before runtime contracts |
| `PPK-*` | provider/fake/live route | before provider prerequisites |
| `DRA-*` | deep research automation | before fake-provider and switch tests |
| `RPK-*` | release/install/ops | before go/no-go acceptance |

Each packet must name:

- write set;
- forbidden surfaces;
- owner docs;
- dependencies;
- expected outputs;
- verification commands;
- negative/recovery checks;
- closeout claim ceiling.

## 9. Core Script Matrix

Every planned script row must include:

| Column | Meaning |
| --- | --- |
| script path | stable planned path |
| owner package | source owner |
| purpose | one sentence |
| inputs | explicit inputs |
| outputs | receipts/artifacts |
| dependencies | tools/services/packages |
| failure classes | named failures |
| tests | fixture or smoke coverage |
| non-claims | what success does not prove |
| first packet | admission packet |
| placement class | stable `source_wrapper` or scratch/Temp-only probe |

Smoke/probe placement rule:

- One-off smoke, probe, inspector, and disposable harness scripts belong under the project scratch/Temp root, with commands, exit codes, and redacted outputs summarized in the task report.
- Scratch smoke/probe files are not source truth, controller truth, accepted evidence, release input, or default read surfaces.
- Promote smoke/probe logic into `scripts/` only through an explicit controller packet as a stable `source_wrapper`; promoted wrappers must call typed APIs or binaries, keep business logic in owned source modules, define outputs and failure classes, include negative cases, and state non-claims.
- Smoke-named rows below are stable wrapper candidates, not permission to persist every packet-local probe under source.

Minimum script families:

- record validators;
- fixture checkers;
- environment checks;
- provider profile and fake-provider checks;
- research report validators;
- UI copy audits;
- UI geometry/source-evidence audits;
- screenshot/browser smoke;
- command-map audits;
- release diagnostics and redaction.

Minimum named stable script count for a governed new project is 10. Names can be adapted to the repo, but these responsibilities must exist before the plan is called implementation-ready:

| Responsibility | Example Stable Path | First Useful Packet |
| --- | --- | --- |
| environment route check | `scripts/check-environment.ps1` | `IPK-001` |
| TruthDocs shape validation | `scripts/validate-truthdocs.ps1` | `IPK-001` |
| route-index validation | `scripts/validate-route-index.ps1` | `IPK-001` |
| fixture inventory validation | `scripts/validate-fixtures.ps1` | `IPK-002` |
| record/claim validator | `scripts/validate-records.ps1` | `IPK-003` |
| fake-provider smoke | `scripts/run-fake-provider-smoke.ps1` | `PPK-001` |
| provider profile validation | `scripts/validate-provider-profile.ps1` | `PPK-001` |
| research report validator | `scripts/validate-research-report.ps1` | `DRA-001` |
| UI copy exposure audit | `scripts/validate-ui-copy.ts` | `UIK-001` |

## 10. Task/Goal Loop And Report Boundary

Do not leave future coding threads with only a summary plan. Create text-driven task and goal loops that can be executed after context compression.

Required loop structure:

| Surface | Required Contract |
| --- | --- |
| task index | lowest open task selection rule, dependency states, current next task |
| goal index | same-number mapping invariant and goal list |
| task files | one `MTL-###` file per task with preconditions, owner docs, allowed writes, forbidden writes, work items, verification, closeout |
| goal files | one `GL-###` file per task with hard acceptance gates, required evidence, review gate, blockers |
| review standard | allowed verdicts only `PASS`, `BLOCK`, `WAIVED_BY_CONTROLLER`; independent review requires carrier receipt |
| report policy | ordinary development threads write only selected `TruthDocs/Tasks-Reports/MTL-###/report.md` |
| final coverage audit | every final `AC-*` row maps to at least one same-number task/goal owner |

Hard rules:

- Task count and goal count must match by id.
- A task report is candidate context, not controller truth.
- Queue/task/goal state advances only through controller-update, not from a development report.
- Planned loops after the first bounded packets must split when they mix UI, backend, storage, provider, security, release, or runtime-record ownership classes.
- Review blocks shallow implementation, placeholder modules, harness-only proof, happy-path-only checks, same-thread self-certification, and unsupported independent-audit wording.

## 11. Standing Autonomy And Goal Runtime

If the user wants `run until done`, all-tasks automatic advancement, heartbeat/scheduler continuation, or standing execution permission, add a controller-owned standing-autonomy contract before implementation. If the user explicitly wants native `/GOAL`, Codex Goal, or `create_goal`, additionally record `native_goal_carrier=explicit`; otherwise the loop stays in OZM current-thread text control.

Required fields:

| Field | Required Meaning |
| --- | --- |
| `standing_autonomy_id` | stable mission authorization id |
| `activation_state` | normally `available_not_started` until latest request activates it |
| `authorization_source` | exact latest user request or controller record |
| `mission_objective` | durable final objective, not current packet |
| `default_continuation_rule` | normally `continue_until_hard_stop` |
| `bounded_execution_grain` | one packet or one child packet per evaluator pass |
| `runtime_carrier_posture` | current-thread text control unless runtime bridge exists |
| `background_carrier_posture` | unavailable until heartbeat/scheduler/external harness is proven |
| `latest_request_override_rule` | newest visible user request wins |
| `checkpoint_cadence` | after packet closeout, review block, controller update, compression, and before final claim |

Hard stops:

- stale owner docs or queue;
- unfrozen write set;
- selected packet not ready;
- child split required but absent;
- controller-truth change needed from writer role;
- forbidden write surface;
- missing environment/provider/runtime carrier required by claim;
- unsupported background progress or independent audit claim;
- verification failure outside repair budget;
- review `BLOCK`;
- claim wording exceeds proof or claim ceiling.

Standing autonomy is an authorization layer, not evidence. It does not prove background execution, independent review, queue advancement, provider permission, or final completion.

Routine loop output discipline is a communication contract, not a proof waiver. It keeps active threads concise, but hydration receipts, dispatch freeze, review/subagent classification, claim ceiling, and closeout remain mandatory when their gates fire.

## 12. Acceptance Checklist

- [ ] Claim ceiling is explicit.
- [ ] Final objective outranks MVP slice success.
- [ ] Control surfaces exist and are indexed.
- [ ] Route index prevents bulk-loading the full corpus.
- [ ] MainTaskLoop and MainGoalLoop are 1:1 and same-number mapped.
- [ ] Tasks-Reports is the only TruthDocs write surface for ordinary development threads.
- [ ] Goal review has blocking verdicts and carrier requirements for independent audit.
- [ ] Final acceptance rows map to task/goal owners and broad loops split before dispatch.
- [ ] Standing autonomy, if desired, separates mission authorization from bounded packet execution and records current-thread/background carrier posture.
- [ ] Goal/runtime reentry gate is present in repo instructions and requires post-compaction child-skill hydration before tool use or file mutation.
- [ ] Agentic coding loop output discipline is present in repo instructions and limits routine progress messages to execution action, result, and a current state summary no longer than five lines.
- [ ] Technology stack is exact and deviations are recorded.
- [ ] Source boundaries prevent cross-layer shortcuts.
- [ ] Environment entry route exists before tool discovery.
- [ ] UX interaction surfaces have owners, layers, coordinates, states, and motion when UI/UX is in scope; otherwise `ux_scope=not_applicable_or_deferred` is recorded.
- [ ] Visible copy forbids debug/backend/secret leakage.
- [ ] Image-2/UIREF/atlas outputs remain candidate-only until mapped.
- [ ] Provider route starts with fake provider.
- [ ] Deep research automation stays fake-first and off by default until provider admission.
- [ ] Script matrix is strong enough for future threads to implement without guessing.
- [ ] Ad hoc smoke/probe/inspector/harness scripts default to scratch/Temp and are excluded from source truth, accepted evidence, release input, and default read surfaces.
- [ ] Any smoke/probe logic promoted into `scripts/` is explicitly admitted as a stable `source_wrapper` with typed-API boundaries, output contract, negative cases, and non-claims.
- [ ] Packet ladder names dependencies, write sets, and verification.
- [ ] No runtime, UI, provider, DB, MCP, or release claim is made from planning alone.
